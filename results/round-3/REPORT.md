## What the round showed about the design

These are disclosed here; nothing was changed.

1. **Re-attempts cannot recover an output fault the model repeats.**
   - In every cell without a valid attempt, all three attempts gave the same response bytes and the same token counts (TABLES.md, "Cells without a valid attempt").
   - With temperature 0, a fresh load and no seed, the 3-attempt cap only helps with transient causes, such as a transport error, a timeout or daemon state.
   - The pre-lock smoke records already showed byte-identical outputs across runs. The consequence for the attempt rule was not discussed before the lock.
2. **The S-tier reproducibility bar checks runtime determinism under these conditions, not judge stability.** Every S-tier case in R and R-fast gave the same verdict in all three runs (TABLES.md, "First valid verdict").
3. **Three kinds of output fault ended the three INCOMPLETE papers:**
   - a mechanism class that is not on the list (primary);
   - JSON that does not parse (fast);
   - a context-length stop with an empty response (fast).
   A fix for one does not fix the others.
4. **ATK-005 was valid in round-2.**
   - Round-2's primary judged the same case validly: attack, `assert-weakened` (`results/round-2/regression/receipts.jsonl`).
   - Round-3 changed the anchor (v2), the runtime (0.40.4) and the load condition (fresh). Which of these changes made this case invalid is not known.
5. **Device placement is not among the engine pins.**
   - llama-server chooses the placement from the device memory that is free when the model loads.
   - In all four papers, every load of an arm had the same placement (TABLES.md, "Device placement").
   - The load check was added before K so that a change would be seen before a paper started.
6. **Most generated tokens are not in the receipts.**
   - Receipts keep the daemon's `response` text and its token counts. The count is far larger than the text needs: ATK-005 generated 5354 tokens for a 1442-character response.
   - K-fast's length stops left an empty response.
   - This is an inference from the counts; the generated tokens outside `response` are not recorded anywhere.
7. **`SUMMARY.md`'s "Re-attempted cells: 0" is easy to misread.** It counts only cells that resolved after more than one attempt. The cells without a valid attempt were each attempted three times (`report.json`, `gaps.unresolved`).
8. **Two PREREG sentences conflict.** Addendum 6 says "Any INCOMPLETE, INVALID_PAPER or INVALID_RECORDS paper means round-3 does not pass", and it also calls R-fast and K-fast "observation only; never a round-3 condition". This is moot here because R decided round-3. Any later PREREG should resolve it.
9. **R's lock check came from a script that was not committed.**
   - The script that wrote `lock-check/R.txt` was not committed, and it printed 12-character hash prefixes.
   - A copy that prints full sha256 values, with the same checks, was committed before K (`lock-check/lockcheck.py`).
   - On 2026-10-18 a read-only review recomputed the full values behind R.txt; they match Addendum 6.
