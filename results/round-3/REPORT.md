## What the round showed about the design

These findings are disclosed here; nothing was changed.

1. **Re-attempts cannot recover an output fault that the model repeats.**
   - In every cell without a valid attempt, all three attempts gave the same response bytes and the same token counts (TABLES.md, "Cells without a valid attempt").
   - With temperature 0, a fresh load and no seed, the 3-attempt cap helps only with transient causes: a transport error, a timeout or daemon state.
   - Identical outputs across runs had already been recorded, by the pre-lock smoke runs (`docs/proposals/round-3-PREREG-DRAFT.md`, section 1) and by the T-540 judge smoke (DECISIONS, 2026-10-15). What that means for the attempt rule was not discussed before the lock.
2. **The S-tier repeat checks runtime determinism, not judge stability, under these conditions.** Every S-tier case in R and R-fast gave the same verdict object and the same response bytes in all three runs (TABLES.md, "S-tier cases"). This is not the S-reproducibility bar, which was not scored.
3. **Three kinds of output fault ended the three INCOMPLETE papers.** A fix for one does not fix the others:
   - a mechanism class that is not on the list (primary);
   - JSON that does not parse (fast);
   - a context-length stop with an empty response (fast).
4. **ATK-005 was valid in round-2.**
   - Round-2's primary judged the same case validly: attack, `assert-weakened` (`results/round-2/regression/receipts.jsonl`).
   - Round-3 changed several things, among them the anchor (v2), the runtime (0.40.4), the load condition (fresh), and the context option: `num_ctx` is set to 16384, where round-2's context size was fixed and not recorded (CR-16).
   - Which change made this case invalid is not known.
5. **Device placement is not among the engine pins.**
   - llama-server chooses the placement from the device memory that is free when the model loads.
   - Each arm had one placement over all its loads, across all of its papers (TABLES.md, "Device placement").
   - The load check was added before K so that a change would be seen before a paper started.
6. **The token counts exceed what the recorded responses need.**
   - Receipts keep the daemon's `response` text and its token counts.
   - ATK-005 generated 5354 tokens for a response of 1442 characters, and K-fast's length stops left an empty response (TABLES.md, "Cells without a valid attempt").
   - So for these cells most generated tokens are not in the receipt. This is an inference from the counts: nothing records those tokens.
7. **"Re-attempted cells: 0" in `SUMMARY.md` is easy to misread.** It counts only cells that resolved after more than one attempt. The cells without a valid attempt were each attempted three times (`report.json`, `gaps.unresolved`).
8. **Two sentences in Addendum 6 conflict.**
   - One reads: "Any INCOMPLETE, INVALID_PAPER or INVALID_RECORDS paper means round-3 does not pass".
   - The other calls R-fast and K-fast "observation only; never a round-3 condition".
   - This is moot here, because R decided round-3. A later PREREG should resolve it.
9. **R's lock check was written by an uncommitted script that printed 12-character prefixes.**
   - A copy with the same checks that prints full sha256 values was committed before K (`lock-check/lockcheck.py`).
   - The full values behind `R.txt` (each file's blob at the commit R.txt names, hashed) are in TABLES.md, "The values behind lock-check/R.txt", and they equal Addendum 6.
